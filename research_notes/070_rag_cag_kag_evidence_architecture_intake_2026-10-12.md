## Corrections to the screenshot's simplified taxonomy

| Screenshot claim | Scope-supported assessment |
|---|---|
| RAG always chunks, vector-embeds and uses a vector database | **Overgeneralized.** Dense top-K was in the original model, but lexical BM25 is an evaluated alternative; RAG can use hybrid, lexical or structured retrieval. In the Lewis paper, the Wikipedia index contained 21 million 100-word passages (§3). This is not a prescription for local deployments. |
| RAG is only as good as search results | Useful emphasis but incomplete: document authenticity, version, grounding quality, context use and the generator's behavior also affect correctness. Retrieval alone does not establish that each output is sourced. |
| CAG preloads knowledge, saves KV cache, eliminating retrieval | Accurately describes one CAG configuration **if the relevant corpus fits** and cache reuse is supported. The cache requires invalidation on changes to source, tokenizer, system prompt, model parameters or any incompatible prefix/configuration. These are required implementation considerations, not properties validated by this research note. |
| CAG has no ranking error or almost no delay | No retrieval-ranking stage in the cache-only branch, but model attention/selection can still fail. Context size affects prefill/generation latency and memory; CAG did not win every reported benchmark: HotPotQA large sparse-RAG top-5 BERTScore **0.7535** versus CAG **0.7407** (Chan et al., Table 2). No universal latency advantage is established. |
| KAG turns facts into a graph and makes every reasoning step traceable | The original KAG links structured information to source chunks and supports logical-form planning, but graph extraction, entity linking and solver steps can be wrong. Existence of a source link ≠ validated source content; accessible intermediate traces ≠ correctness of a final answer. |
| KAG is always strongest for medicine/law/finance | **Unsupported universal ranking.** Liang et al. report bounded multi-hop QA and selected e-government/e-health applications, not a cross-domain superiority theorem or comprehensive law/finance evaluation. |

A graph is a **map of asserted relationships**, not a new truth oracle. A cache is a **reusable derivation**, not a fresh authority source. Retrieval outputs and social posts remain untrusted data; they cannot supply new control instructions or override preregistered criteria. A signed file authenticates bytes/identity only to the extent supported by the signature process, not real-world truth.

## S25 and local-first deployment risks to measure, not assume

- KV-cache memory grows with sequence length, layer count, KV head count and dtype; flagship NPU/GPU availability does not guarantee feasible full-prefix caching. Determine limits empirically for the **specific model build and backend**, not generic context-window advertising.
- Quantized model weights do **not** imply proportionally quantized KV state. Track cold prefill, warm-query latency, page faults, RAM footprint and thermal DEFER policy. Do not claim Qualcomm QNN/HTP use without backend-specific device traces.
- Begin with deterministic lexical search over hashed Markdown/code/PDF extract manifests, optionally add local vector retrieval. Keep indexing out of the source-of-truth and compare retrieved bytes against current pinned revisions.
- For graph experiments, distinguish manually verified edges from model-extracted edges; preserve source-span provenance and negative/contradicting relations. Semantic equivalence must not erase byte identities or source revisions.

## Proposed falsifiable evaluation — NOT REGISTERED OR EXECUTED

**Prerequisites:** freeze a source manifest and timestamped corpus; define permitted mutable sources, document freshness cutoffs, evaluator/answer rubric, random seeds where relevant, independent scoring, exact cache invalidation conditions and independent hold-out questions.

**Comparable arms:** baseline no retrieval; lexical RAG; optional local dense RAG; CAG on a fixed *small* corpus; source-linked graph retrieval / KAG; and hybrid only if its extra cost is justified. Match the available evidence and token budget per task; distinguish retrieval quality from generation quality.

**Adversarial controls and negative examples:**
1. Hold-out fact only present in one correct document (retrieval recall control).
2. Intentionally stale but correctly cached prefill following a source revision (cache invalidation control).
3. Incorrect or fabricated graph edge linked to a real but irrelevant source (provenance-truth distinction).
4. Contradictory sources with different trust levels or revisions; must not silently assert one answer.
5. Prompt injection embedded in a retrieved page or graph node, including instructions to modify GitHub or score claims; must not cross the control boundary.
6. Source removal, renaming, rollback and duplicated identifiers; flag missing/ambiguous provenance.
7. Legitimate first-use, ordinary question, and refusal cases to prevent always-refuse vacuity.
8. Wrong-answer/high-citation control: generated statement inconsistent with retrieved bytes.

**Measurements:** source-hit recall, supported-claim precision, unsupported-assertion rate, correct abstentions, contradiction handling, freshness, citation-span integrity, median/p95 wall time (cold/warm), RAM and measured device thermal envelope. Ensure scored answers cannot use held-out labels or grader expectations. Predefine what constitutes a meaningful benefit and cost threshold before a confirmatory run.
