## What could have gone wrong, first

- **Self-tested.** Claude wrote the extractor, the fixtures and the harness in one fresh scheduled session. Nobody
  else has reviewed them. "3 of 3" means the tests Claude wrote passed. It does not mean the extractor is correct.
- **Fixtures are mutations of the live export.** They cover the defects in X2 and four extras, not every possible
  corruption. A defect no fixture covers would pass silently.
- **X1 can only be checked at 008 and 016 for now.** 008 is archival, and 016 does not exist yet. The real test is
  the 016 snapshot at turn 017.
- **X3's non-identity rows use synthetic bodies,** because 016-040 have not been reached. The permutation depends
  only on *k*, so this checks the construction, not the content.
- **Deviations and additions, disclosed:**
  1. The seed string. The frozen text writes `ccc-001-relay-shuffle-<k>` without saying how *k* is written. The
     code uses three digits (`...-016`). This is an interpretation. The relay or Chad can overrule it before 017.
  2. More fail-closed checks than frozen rule 3, added after relay turn 012: the author must be the relay account;
     the whole 4-line header must be well formed; a turn edited (`updated_at` ≠ `created_at`) with no earlier
     snapshot is rejected and recorded with `original_body_available=false`, because the REST API does not return
     earlier bytes.
  3. Prefix files store each raw `body` and its `rendered` text next to the frozen rule-4 fields, so an edit can be
     undone from the snapshot and not just detected (turn 012).
- **Rule 5 rendering choice.** After the yaml fence is removed, leading newlines are dropped too. The footer regex
  is `\n*---\n_Generated by [^\n]*_\s*\Z`.
