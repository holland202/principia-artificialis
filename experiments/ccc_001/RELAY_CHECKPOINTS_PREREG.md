## Scope

The question this serves (CCC-001, unchanged): does a coherent accumulated conversation change a fixed model's robust
correctness more than matched controls? This file fixes only **which prefixes of the relay exist as data, and how they
are cut and rendered**. It registers no hypothesis about the model, no endpoint and no threshold.

## Extraction rule (deterministic)

1. **Source:** `gh api repos/holland202/principia-artificialis/issues/172/comments --paginate`, raw JSON kept intact.
2. **Relay turn:** a comment whose body starts with a `yaml` fence whose first line is
   `note: ccc-relay/<claude|chatgpt>/<NNN>`. All other comments (Chad's, reminders) are excluded and listed by ID.
3. **Order:** by NNN. Fail closed (nonzero exit, no prefix written) if: a number in 001..*k* is missing; a number is
   claimed twice; an odd turn is not `claude` or an even turn is not `chatgpt`; NNN order disagrees with
   `(created_at, id)` order.
4. **Snapshot:** the first Claude turn after a checkpoint is reached (017, 025, 033, or the stop export) writes
   `results/ccc_001/relay_prefix_<k>.json`: per turn, NNN, speaker, comment ID, `created_at`, `updated_at` and the
   SHA-256 of the raw UTF-8 body, plus the SHA-256 of the whole file in the commit message. Later exports are compared
   with it; any changed body is a recorded defect and the snapshot governs.
5. **Rendered text:** per turn, delete the leading yaml fence and a trailing `---` + `_Generated by …_` footer. Keep
   everything else byte for byte, including wikilinks, code blocks and credit lines.
6. **Speaker mapping (fixed):** Claude turns are `user` messages and ChatGPT turns `assistant` messages, in NNN order.
   No system message is added by the extraction.

## Order-shuffle control (proposed in turn 010; registered here as a construction, not a prediction)

Prefix *k* with Claude's turns permuted among the odd slots and ChatGPT's among the even slots, by
`random.Random(int(sha256(b"ccc-001-relay-shuffle-<k>").hexdigest(), 16)).shuffle`, applied to odd then even. It keeps
the role structure, alternation and exact text multiset; only the sequence changes. A **matched-guidance control**
(same roles, token budget and task-relevant guidance, different conversation) is **not** registered here.

## Predictions for the extractor, once built (M3 anti-vacuity)

- **X1:** on the live thread, asked for a checkpoint whose turn does not exist yet, it returns MISSING and exits
  nonzero; asked for one that exists, it writes the prefix and exits 0.
- **X2:** each fixture (a duplicated NNN, a gap, a swapped speaker, a body edited after the snapshot) is rejected,
  exit nonzero.
- **X3:** the shuffle control has the same rendered-text multiset and alternation as its prefix, and is not the
  identity permutation for *k* ≥ 016.

## Limits

- Both AIs know the hypothesis and that they are recorded; they can shape the text, though not where it is cut.
- Turns cite each other by number in their bodies, so the shuffle control keeps references that now point the wrong
  way. That is part of what it tests, and it also makes the control less fluent than the original.
- The archival 008 boundary and every prefix are read by both AIs while writing. Nothing here is a sealed test item.
