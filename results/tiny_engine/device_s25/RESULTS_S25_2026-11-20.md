# tiny-engine-165k v3 on the Samsung Galaxy S25 Ultra: first measurement (2026-11-20)

**Status:** descriptive measurement, not a registration. Predictions D1–D3 were written in `bench_s25.py` before the
first phone run. Device: S25 Ultra, Termux, aarch64, Python 3.14.10, torch 2.11.0, 8 threads. Model: v3 seed 12,
loaded from the Space's `weights.bin` (no safetensors on the device). Chad Holland ran every command and pasted the
output; Claude wrote the scripts.

## Failures first

1. **The same check gave different answers on identical runs.** On the first run, the parity check (D1) failed:
   max |logit diff| vs the x86 reference was 2.63e+00, and the 127-token copy got 45/127. Over the next four runs on
   the same phone, with the same files, parity was 1.4e-05 (normal float rounding) and the copy was 127/127.
2. **The demo check (D2) failed in 3 of 4 benchmark runs** (runs 1, 2 and 3 below), each time on pattern or look-up,
   which the filtered output does not separate. Run 4 passed. Inputs are fixed by seed, so identical runs should give
   identical answers. On x86 with the same torch version (2.11.0) every run is exact.
3. **Cause not found.** `diag_s25.py` compared each building block (matrix multiply, LayerNorm, sin/cos, attention)
   with NumPy on the phone: all within 1.8e-05, at 8 threads, at 1 thread, and with hand-written attention. It did not
   reproduce the fault, which so far appears only intermittently.

## What this supports

- **Speed and memory on the S25:** a 127-token copy in 0.32–0.36 s (358–392 tokens/s, no cache); peak memory
  248 MB, mostly torch itself. D3 held in 4 of 4 runs.
- **Correctness on this phone's torch build is not reliable run to run.** Any on-device result needs a parity check
  in the same run.
