## Discovery and intake
1. Read current public PA notes, open registrations and recent intake records for topic overlap; send no unpublished data or owner prompts to external providers. Record the exact public query, UTC window, provider/version/commit, run time, enabled sources, actual sources queried, errors and omissions. Distinguish ENGINE, WEB-ONLY and NOT RUN. Missing sources are unknown coverage, not zero results.
2. Retrieve primary publications/versioned preprints, official code/releases, datasets and independent commentary. Social engagement can prioritize reading, never count as verification. Deduplicate by DOI/arXiv ID and version, canonical URL, repository/commit and underlying origin; mirrors or summaries of one source are one provenance family.
3. For each candidate record source URL, authors as permitted, publication date and version, retrieval date, pinpoint claim location, exact scope, whether code/data are accessible, limitations and contradictory evidence. Retain permissible external source material verbatim with SHA-256 in the existing record under C-EXT; where retention is not permitted, record the restriction and do not treat the missing artifact as verified. Never store credentials, personal posts with unnecessary identifying details, private or restricted material in public PA. Record source-check failures explicitly; do not promote a claim missing at its cited source.
4. Map each candidate to a specific public PA question or state no match. Search older prior art before suggesting novelty. Separate author-reported results, checked source descriptions, recomputed results and fresh reproduction. Do not quote numeric outcomes as PA results. Propose the smallest falsifier, rival explanation and available inputs; no new experimental run without separate W2/W4 authority. Preserve rejected, duplicate and blocked items.
5. Write an additive dated intake under `references/intake_YYYY-MM-DD/` (avoid collisions by adding a suffix if necessary). Failures and unknown coverage first; then candidate table, provenance, dispositions, next test and AI/human review labels. Use dispositions CANDIDATE / DEFER / REJECT / DUPLICATE (triage labels only). No eligible candidate is a valid outcome.
6. Claude prepares/checks the intake; ChatGPT attacks claim-to-source mapping, duplicates, rival explanations and any proposed test; agreement is not independent validation (M10/C-INDEP). Use the existing PR note protocol and [hub #183](https://github.com/holland202/principia-artificialis/issues/183). No external posting, automated merges or changes to schedules.
